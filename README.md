# PDF RAG Lab

PDF 문서를 업로드하고 질문하면 관련 내용을 검색하여 근거 페이지와 함께 답변하는 RAG 서비스를 단계별로 구현하는 학습 프로젝트입니다.

완성된 코드를 빠르게 만드는 것보다 RAG 시스템의 각 구성 요소가 왜 필요한지 이해하고, 직접 구현하는 것을 목표로 합니다. No codex!!

## 프로젝트 목표

- PDF에서 페이지별 텍스트를 추출한다.
- 텍스트를 검색하기 좋은 크기로 나눈다.
- 각 텍스트 조각을 임베딩한다.
- 질문과 관련된 문서를 검색한다.
- 검색 결과를 바탕으로 답변을 생성한다.
- 답변과 함께 근거 페이지를 제공한다.
- 검색 품질과 답변 품질을 평가한다.
- 실제 서비스에서 발생하는 비용과 성능 문제를 이해한다.

## 기술 스택

- Python
- FastAPI
- PyMuPDF
- pytest

초기 단계에서는 RAG의 내부 동작을 직접 이해하기 위해 LangChain이나 LlamaIndex를 사용하지 않습니다.

## 학습 원칙

1. 전체 기능을 한꺼번에 구현하지 않는다.
2. 각 기능이 필요한 이유를 이해한 뒤 코드를 작성한다.
3. 파싱, 검색, 생성 등 서로 다른 책임을 분리한다.
4. 정상 동작뿐만 아니라 실패하는 경우도 테스트한다.
5. 각 코드가 어떤 역할을 하는지 직접 설명할 수 있도록 학습한다.
6. 단계별로 배운 내용과 시행착오를 기록한다.

## 현재 구현

`POST /papers` 엔드포인트에 PDF 파일을 업로드하면 페이지별 텍스트를 추출하여 반환합니다.

응답에는 다음 정보가 포함됩니다.

- 업로드한 파일명
- 전체 페이지 수
- 각 페이지의 번호
- 각 페이지에서 추출한 텍스트

### 응답 예시

```json
{
  "filename": "example.pdf",
  "total_pages": 1,
  "pages": [
    {
      "page_number": 1,
      "text": "추출된 페이지 내용"
    }
  ]
}
```

## 학습 기록

### Day 1: PDF 업로드와 파싱 (2026.09.11)

#### 구현한 내용

- FastAPI의 `UploadFile`을 이용한 PDF 업로드 API
- PyMuPDF를 이용한 페이지별 텍스트 추출
- PDF 파싱 로직과 API 로직 분리
- 잘못된 파일에 대한 예외 처리
- pytest를 이용한 파서 단위 테스트
- FastAPI `TestClient`를 이용한 API 테스트

#### 배운 내용

##### 1. 업로드된 파일은 bytes로 읽힌다

```python
pdf_bytes = await file.read()
```

`file.read()`는 파일 경로가 아니라 업로드된 파일의 실제 내용을 bytes 형태로 반환합니다.

##### 2. PDF에 글자가 보인다고 항상 텍스트를 추출할 수 있는 것은 아니다

일반적인 텍스트 PDF에는 실제 문자 데이터가 들어 있으므로 `page.get_text()`로 추출할 수 있습니다.

반면 스캔한 문서는 글자가 이미지의 일부로 저장되어 있을 수 있습니다. 이 경우 화면에는 글자가 보여도 텍스트 추출 결과는 비어 있을 수 있으며, 별도의 OCR 처리가 필요합니다.

##### 3. strip으로 실제 텍스트가 있는지 확인할 수 있다

```python
text = page.get_text().strip()
```

`strip()`은 문자열 앞뒤의 공백, 탭, 줄바꿈을 제거합니다. 이를 통해 공백 문자만 있는 페이지를 실제 텍스트가 없는 페이지로 판단할 수 있습니다.

##### 4. any로 전체 PDF에 텍스트가 있는지 확인할 수 있다

```python
if not any(page_data["text"] for page_data in pages):
    raise PdfParsingError("PDF에서 텍스트를 찾을 수 없습니다.")
```

각 페이지의 텍스트 중 하나라도 비어 있지 않으면 `any()`는 `True`를 반환합니다. 모든 페이지가 비어 있으면 `PdfParsingError`를 발생시킵니다.

##### 5. 파서와 API는 서로 다른 오류를 사용한다

파서는 PDF 처리 과정에서 발생한 문제를 `PdfParsingError`로 표현합니다.

API는 이 오류를 잡아서 클라이언트가 이해할 수 있는 HTTP 400 응답으로 변환합니다.

```python
try:
    pages = extract_pages(pdf_bytes)
except PdfParsingError as error:
    raise HTTPException(
        status_code=400,
        detail=str(error),
    ) from error
```

`detail=str(error)`는 오류 메시지를 HTTP 응답에 담습니다.

`from error`는 새로 발생시킨 `HTTPException`과 원래의 `PdfParsingError` 사이의 원인 관계를 남깁니다.

##### 6. pytest로 예외 발생을 확인할 수 있다

```python
with pytest.raises(PdfParsingError):
    extract_pages(b"")
```

해당 코드에서 `PdfParsingError`가 발생하면 테스트가 통과합니다. 오류가 발생하지 않거나 다른 종류의 오류가 발생하면 테스트가 실패합니다.

#### 발생한 문제와 해결 과정

페이지 데이터에서 텍스트를 가져오는 코드를 다음과 같이 작성하여 `KeyError`가 발생했습니다.

```python
page_data[text]
```

이 코드에서 `text`는 문자열 키가 아니라 이전 반복에서 저장된 페이지 본문을 가리키고 있었습니다.

딕셔너리의 실제 키인 `"text"`를 문자열로 지정하여 해결했습니다.

```python
page_data["text"]
```

이 과정을 통해 Python 딕셔너리의 키를 문자열로 사용할 때는 따옴표가 필요하다는 점을 확인했습니다.

또한 서버 트레이스백은 아래쪽부터 살펴보면 실제 오류 종류와 오류가 발생한 파일 및 줄을 빠르게 찾을 수 있다는 것을 배웠습니다.
