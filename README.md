PDF RAG Lab

PDF 문서를 업로드하고 질문하면 관련 내용을 검색하여 근거 페이지와 함께 답변하는 RAG 서비스를 단계별로 구현하는 학습 프로젝트입니다.

완성된 코드를 빠르게 만드는 것보다 RAG 시스템의 각 구성 요소가 왜 필요한지 이해하고, 직접 설명하고 검증할 수 있는 상태를 목표로 합니다. AI 도구는 완성품을 대신 만드는 용도가 아니라 튜터와 코드 리뷰 도구로 활용합니다.

프로젝트 목표

* PDF에서 페이지별 텍스트를 추출한다.
* 텍스트를 검색하기 좋은 크기로 나눈다.
* 청크가 어느 페이지에서 나온 내용인지 추적한다.
* 각 청크와 질문을 임베딩한다.
* 질문과 관련된 청크를 검색한다.
* 검색 결과를 바탕으로 답변을 생성한다.
* 답변과 함께 근거 페이지를 제공한다.
* 검색 품질과 답변 품질을 평가한다.
* 실제 서비스에서 발생하는 비용과 성능 문제를 이해한다.

기술 스택

* Python

초기 단계에서는 RAG의 내부 동작을 직접 이해하기 위해 LangChain이나 LlamaIndex를 사용하지 않습니다.

핵심 설계

페이지를 연결한 뒤 청킹하는 이유

PDF의 페이지 경계는 문장이나 의미의 경계와 일치하지 않을 수 있습니다. 문장이 다음 페이지로 이어지는 경우 페이지별로 따로 청킹하면 문맥이 끊어질 수 있습니다.

따라서 페이지별 텍스트를 \n으로 연결한 뒤 하나의 문서로 청킹합니다.

1페이지 텍스트
\n
2페이지 텍스트
\n
3페이지 텍스트

페이지 위치를 기록하는 이유

페이지들을 하나의 문자열로 연결하면 각 내용의 원래 페이지를 잃을 수 있습니다. 이를 방지하기 위해 합쳐진 문자열에서 각 페이지가 차지하는 범위를 기록합니다.

page_ranges = [
    {"page_number": 1, "start": 0, "end": 500},
    {"page_number": 2, "start": 501, "end": 980},
]

청크의 문자 범위와 페이지 범위를 비교하면 청크가 걸쳐 있는 페이지를 찾을 수 있습니다.

{
    "chunk_index": 0,
    "page_numbers": [1, 2],
    "text": "청크 텍스트"
}

청크 크기와 overlap

chunk_size는 하나의 청크에 포함할 최대 문자 수입니다.

overlap은 이전 청크의 마지막 일부를 다음 청크에도 포함하는 크기입니다. 청크 경계에서 문장과 문맥이 끊기는 문제를 줄이는 데 사용합니다.

chunk_size = 100
overlap = 20
이동 거리 = 100 - 20 = 80

청크 크기에는 트레이드오프가 있습니다.

* 작은 청크는 관련 내용과 페이지를 정밀하게 찾을 수 있지만 문맥이 부족할 수 있습니다.
* 큰 청크는 충분한 문맥을 제공하지만 관련 없는 내용과 페이지까지 포함할 수 있습니다.
* overlap을 크게 하면 문맥 보존에는 도움이 되지만 중복 데이터와 처리 비용이 증가합니다.

배운 내용

업로드된 파일은 bytes로 읽힌다

pdf_bytes = await file.read()

file.read()는 파일 경로가 아니라 업로드된 파일의 실제 내용을 bytes 형태로 반환합니다.

PDF에 글자가 보인다고 항상 텍스트를 추출할 수 있는 것은 아니다

일반적인 텍스트 PDF에는 실제 문자 데이터가 들어 있으므로 page.get_text()로 추출할 수 있습니다.

스캔한 문서는 글자가 이미지의 일부로 저장되어 있을 수 있습니다. 이 경우 화면에는 글자가 보여도 텍스트 추출 결과는 비어 있을 수 있으며 별도의 OCR 처리가 필요합니다.

any()로 전체 PDF에 텍스트가 있는지 확인할 수 있다

if not any(page_data["text"] for page_data in pages):
    raise PdfParsingError("PDF에서 텍스트를 찾을 수 없습니다.")

각 페이지의 텍스트 중 하나라도 비어 있지 않으면 any()는 True를 반환합니다. 모든 페이지가 비어 있으면 PdfParsingError를 발생시킵니다.

파서와 API는 서로 다른 오류를 사용한다

파서는 PDF 처리 과정에서 발생한 문제를 PdfParsingError로 표현합니다. API는 이 오류를 잡아 클라이언트가 이해할 수 있는 HTTP 400 응답으로 변환합니다.

try:
    pages = extract_pages(pdf_bytes)
except PdfParsingError as error:
    raise HTTPException(
        status_code=400,
        detail=str(error),
    ) from error

pytest.raises()로 예외 발생을 검증할 수 있다

with pytest.raises(PdfParsingError):
    extract_pages(b"")

예상한 PdfParsingError가 발생하면 테스트가 통과합니다. 오류가 발생하지 않거나 다른 종류의 오류가 발생하면 테스트가 실패합니다.

발생한 문제와 해결 과정

페이지 데이터에서 텍스트를 가져오는 코드를 다음과 같이 작성하여 KeyError가 발생했습니다.

page_data[text]

이 코드에서 text는 문자열 키가 아니라 이전 반복에서 저장된 페이지 본문을 가리키고 있었습니다.

딕셔너리의 실제 키인 "text"를 사용하도록 수정했습니다.

page_data["text"]

또한 서버 트레이스백은 아래쪽부터 살펴보면 실제 오류 종류와 오류가 발생한 파일 및 줄을 빠르게 찾을 수 있다는 점을 배웠습니다.

배운 내용

청킹이 필요한 이유

PDF 전체나 한 페이지 전체를 검색 단위로 사용하면 여러 주제가 하나의 검색 결과에 섞일 수 있습니다. 긴 텍스트를 작은 청크로 나누면 질문과 관련된 부분을 더 정밀하게 검색할 수 있습니다.

overlap이 필요한 이유

문장이나 중요한 정보가 청크 경계에서 잘릴 수 있습니다. 이전 청크의 마지막 일부를 다음 청크에도 포함하여 경계 주변의 문맥을 보존합니다.

잘못된 설정은 무한 반복을 만들 수 있다

step = chunk_size - overlap

overlap이 chunk_size보다 크거나 같으면 이동 거리가 0 이하가 됩니다. 시작 위치가 앞으로 이동하지 않아 반복문이 끝나지 않을 수 있으므로 해당 설정을 미리 거절합니다.

페이지 경계와 의미 경계는 다를 수 있다

PDF의 문장이 다음 페이지로 이어질 수 있기 때문에 페이지별로 완전히 분리하여 청킹하면 문맥이 끊길 수 있습니다.

페이지들을 연결해 청킹하되, 각 페이지의 문자 범위를 별도로 기록하여 문맥과 출처 정보를 함께 보존합니다.

청크의 출처와 답변의 정확한 근거는 다를 수 있다

page_numbers: [1, 2]는 해당 청크가 1페이지와 2페이지의 내용을 포함한다는 뜻입니다. 실제 답변에 사용된 문장이 2페이지에만 있을 수도 있습니다.

현재 단계에서는 청크가 걸친 모든 페이지를 안전하게 반환합니다. 이후 답변 생성 단계에서는 페이지 표시를 컨텍스트에 포함하여 더 정밀한 인용 방식을 실험할 예정입니다.

PDF 텍스트 추출 결과는 항상 깔끔하지 않다

PDF는 화면에 보이는 방식과 내부에 문자가 저장된 방식이 다를 수 있습니다.

실제 강의자료를 테스트하면서 다음 현상을 확인했습니다.

* 슬라이드의 줄바꿈이 다수의 \n으로 추출됨
* 특수 글꼴의 글머리표와 기호가 ,  등의 문자로 추출됨
* 문자 수가 적은 슬라이드 여러 장이 하나의 청크에 포함됨

현재 전처리에서는 불필요한 공백과 빈 줄만 안전하게 제거합니다. 특수문자를 무조건 삭제하면 글머리표, 화살표, 수학 기호의 의미를 잃을 수 있으므로 추후 별도로 다룹니다.

또한 일반 문서와 강의 슬라이드는 적절한 청킹 방식이 다를 수 있음을 확인했습니다. 이후 검색 품질 평가 단계에서 문서 유형, 청크 크기, 페이지 경계 처리 방식을 비교할 예정입니다.

발생한 문제와 해결 과정

Python 가상환경 불일치

시스템에 설치된 pytest와 .venv의 Python이 서로 다른 환경을 사용하여 모듈을 찾지 못하는 문제가 발생했습니다.

다음과 같이 현재 가상환경의 Python을 통해 테스트를 실행하도록 통일했습니다.

python -m pytest

Git에 Python 캐시 파일이 포함됨

__pycache__와 .pyc 파일은 Python이 자동으로 생성하는 파일이며 실행할 때마다 변경됩니다. 해당 파일들을 .gitignore에 추가하고 Git의 추적 대상에서 제거했습니다.

__pycache__/
*.py[cod]
.pytest_cache/
.venv/
